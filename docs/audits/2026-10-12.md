# Code Audit - 12 October 2026

Scope: current local SquadSlot source, dependency lockfile, Docker configuration,
authentication, active-squad permissions, scheduling, calendar exports, backups,
Discord, push notifications, service worker and main React data flows. This is a
code review with regression tests, not an external penetration test or a guarantee
that every vulnerability has been found. No production data or live notification
services were used, and nothing was deployed or pushed.

## Findings Fixed

### High Priority

- **Unhandled asynchronous API errors could stop the server.** Express 4 does not
  automatically catch rejected async handlers. A malformed game-options array was
  one reachable trigger. Added an async error wrapper, input validation, and an
  error handler after push routes. Parser errors now return 400/413 rather than 500.
- **Availability queries could monopolize the server.** Authenticated clients
  could request thousands of years of recurring expansion synchronously. Both
  availability endpoints now reject invalid dates, reversed ranges and ranges
  longer than 366 days.
- **Backup restores could revive invalidated sessions.** Restoring the saved
  session version allowed old cookies to work again. Each restored account gets
  a fresh random session version; the restoring administrator also signs out.
  Restore audit entries no longer assume the current administrator exists in the
  restored database.
- **Known dependency advisories and an unsupported Docker runtime.** The initial
  npm audit reported 15 affected packages (including transitive development tools).
  Compatible updates reduced this to zero. Severity labels are advisory metadata,
  not a claim that every advisory was remotely exploitable in SquadSlot. Docker
  now uses Node 22 LTS instead of Node 20.

### Permissions And Hardening

- Uninvited squad members could vote on proposals. Both API and UI now require an invitation.
- Forwarded host headers were trusted even with proxy trust disabled. Origin checks and generated subscription URLs now respect the configured proxy boundary.
- Password creation accepted values beyond bcrypt's 72-byte limit, silently making different long passwords equivalent. New passwords are bounded by UTF-8 byte length; existing logins remain compatible.
- Signed Discord callbacks lacked an age check and bypassed temporary-password restrictions. Old signatures and restricted accounts are now rejected; duplicate Discord ID mappings are blocked or fail closed.
- Session tokens now use constant-time signature comparison and reject invalid expiry, user IDs, versions and extra token segments.
- API responses use `Cache-Control: no-store`; token-bearing calendar feeds bypass the service worker. Its cache version is bumped to remove older cached feeds on activation.
- Expired authentication-rate-limit buckets are periodically removed; password changes also have an attempt limit.

### Scheduling And Client Bugs

- Repeating an accepted Discord RSVP could count the user against a full event and move them to the waitlist. Unchanged responses are now idempotent.
- Waitlist promotion could silently double-book a player. It now skips conflicting candidates and does not promote ended events.
- Best slots sampled only the start of an evening hour, missing daytime and partial-hour overlaps and overstating availability. Suggestions now use actual boundaries and exclude committed intervals throughout the suggested window.
- Overlapping timer/manual reminder sweeps could both send the same notification before either recorded delivery. They now share one in-flight sweep.
- Event expiry used the browser's interpretation of displayed local times, including the wrong day after midnight. It now uses the canonical UTC end timestamp.
- Dashboard invite counts were capped by the four-item preview list. Totals now use all pending events.
- Older Steam searches could overwrite newer results. Responses are checked against the latest request; account data is cleared on sign-out and session expiry.
- Calendar exports now normalize CR/LF text and fold long lines at UTF-8-safe 75-octet boundaries.
- Calendar subscription URLs now prefer Admin's saved App URL consistently with push/Discord configuration.
- Steam timeouts remain active while reading/parsing the response body.

## Remaining Risks And Follow-Up

- Registration follow-up implemented: new accounts now require administrator
  approval and have no session or squad membership while pending. Admin can close
  registration completely. Existing accounts retain access; review pre-upgrade
  accounts and verify requests with friends before approval. First-admin setup
  must still be completed before exposing a fresh installation publicly.
- Discord IDs are still manually entered, not verified with OAuth. Duplicate IDs
  are now blocked, but a proper ownership-verification flow is preferable.
- Scheduling follow-up implemented: shared displays/inputs consistently use squad
  time, calendar availability exports use UTC, and mixed-device/profile timezone
  browser tests cover presets and DST validation. Missing/repeated clock-change
  endpoints are rejected for one-off entries and skipped for weekly occurrences.
  Overnight creation and choosing between repeated-hour offsets remain unsupported.
- Cross-squad conflicts, host creation/finalisation and attendee rescheduling
  checks now run before changes. Waitlists store queue-entry timestamps and
  recheck conflicts on promotion. Historical queue timestamps cannot be recovered;
  existing queues preserve their previous order on migration.
- Backup hardening follow-up implemented: new exports require encryption, restores
  require confirmation, and calendar subscription links are revoked by default.
  Legacy JSON imports remain supported. Decrypted contents still contain password
  hashes and configuration secrets; protect legacy files, retain the original
  encryption keys separately, and verify recovery on an isolated installation.
  Administrators can explicitly preserve trusted subscription links during restore.
- Proxy follow-up: exact-IP Cloudflare Tunnel trust is available through
  `TRUSTED_TUNNEL_IPS`, with deployment guidance for connector `192.168.1.196`.
  API/account/backup limits and bounded authentication counters are implemented.
  Pending-account and scheduling row quotas limit growth, but are not physical
  disk quotas. Audit/delivery logs and WAL still need monitoring. Verify the
  actual socket peer on deployment, restrict origin access with firewall rules,
  and retain edge-level protection against distributed abuse. Legacy one-hop
  trust remains available with a warning for compatibility.
- The operator reports successful live push and Discord deliveries. Automated
  transport tests remain isolated/stubbed; no new live messages were sent during
  the protection follow-up.
- Authentication, Admin, calendar, availability and session creation have now
  been extracted into feature modules. The shared shell and redesigned calendar
  use scoped styles, with their old global overrides removed. Dashboard, profile
  and several smaller views still use the entry file and shared legacy stylesheet;
  this is an incremental refactor, not a claim that all global styling is gone.
